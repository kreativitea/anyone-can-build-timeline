## Found

No bugs.

### Observation 1: a blocker can still act on posts they cannot see (G7)

After Aiko blocks Dan, Dan's posts disappear for Aiko. But Aiko can still like Dan's post and
reply to it, if she sends its id (`POST /likes {"post_id":4}` → `201`; a reply → `201`).
The rules in AGENTS.md only limit the **blocked** person (`check_not_blocked_by_author`), so this
is the code doing what it says. The page never offers it (Aiko does not see the post).

Question for the owner: should a blocker be stopped too? If yes, it is one more check in
`add_like` and `save_reply` ("the viewer may see this post", through `visible_to`), plus tests.

### Observation 2: zero-width characters are not "hidden characters" (N2)

`HIDDEN_CHARACTERS` (`server.py`, and the same in `app.js`) refuses control characters and
direction marks. It does not include the zero-width space (U+200B), zero-width non-joiner and
joiner (U+200C, U+200D) or U+FEFF. So a place `"Osa​ka"` is saved, and looks exactly like
"Osaka". The same is true for a display name: `"Aiko​ Tanaka"` would look like Aiko's name.

Question for the owner: refuse these in places and display names? Not in post text: U+200D joins
emoji (👩‍💻), so refusing it there would break emoji.
